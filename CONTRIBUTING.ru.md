# Вклад в Salt.Box

## Желаю участвовать в разработке

В настоящее время проект Salt.Box не принимает сторонние изменения.

Воспользуйтесь разделом [обсуждений](/../../issues), чтобы сообщить о проблеме.

Простите за неудобство.

## Рекомендации по использованию Git

Сообщения коммитов должны быть краткими и описательными. Тело (то, что идёт
после первой строки сообщения) является необязательным и может быть полезно для
описания сложных коммитов.

1. Создавайте заголовки не длиннее 50 символов.
2. Создавайте заголовки в повелительном наклонении.
3. Начинайте заголовок с заглавной буквы.
4. И опускайте точку в конце заголовка.
5. Используйте одну пустую строку для отделения заголовка от тела.
6. Создавайте тело сообщения так же кратким и описательным.
7. Используйте `-` для перечисления множественных изменений, если требуется.

Пример:
```
Update CONTRIBUTION.ru.md

- Add Git guidelines section
- Add Changelog section
```

[Хорошая заметка](https://habr.com/ru/articles/416887/) о написании сообщений
коммитов.

Изменения накапливаются в ветках. Ветки должны носить короткие описательные
имена, которые допустимо начинать на `US##_`, где `##` — это номер
пользовательской истории на приватной доске. Пример: `US214_git_guidelines`.

Когда новая возможность готова или ошибка исправлена, ветка может быть слита в
главную ветку. Предпочитаемый способ — использовать команду `git rebase
BRANCH`, тогда как запрос на слияние опционально может быть открыт. Rebase не
создаёт коммита слияния, в отличие от слияния через веб-интерфейс.


## Журнал изменений

Изменения отслеживаются в файле [`CHANGELOG.md`](`/CHANGELOG.md`) в корне
репозитория.

Журнал изменений основывается на руководстве [«Ведите
changelog»](https://keepachangelog.com/ru/1.1.0/)

Существование раздела `[ Unreleased ]` предполагается в промежуточных коммитах,
тогда как коммитах, помечаемых тэгами версий, этот раздел должен
переименовываться в соответствующий версии заголовок.
